# First minute, measured (Agent G), 5 Nov 2026

## 1. Method and what is shaky about it

- Browser: Chrome driven through the claude-in-chrome tools, one window, viewport 1920 x 945 CSS px, DPR 1 [MEASURED: `innerWidth/innerHeight` on a game tab]. The browser UI is in Thai and the YouTube header shows the Premium logo, so this account is Premium [MEASURED: screenshot of a game page, header reads Premium]. Ad timing for normal users is UNVERIFIED; I saw no interstitial anywhere, which proves nothing about non-Premium players. I did not click any ad-badged control.
- Tabs: the hub tab plus at most one game tab at a time (2 tabs total during every game run; 3 for a moment while a stuck tab was being cleared). Every game tab was closed before the next opened.
- "Click" = navigating a fresh tab to `https://www.youtube.com/playables/<game id>` (ids from the CSV). The clock is the page's own `performance.timeOrigin`, so `t0` is the exact navigation start (Thief Puzzle: 2026-11-05T07:09:23.251Z; the other games ran between about 07:10 and 07:25 UTC). [MEASURED]
- Two instruments: (a) a 50 ms poller I injected into the YouTube shell page right after the navigation returned. It logs when the shell's "Loading" overlay text appears and disappears and when the game iframe appears. (b) Screenshots next to `Date.now() - performance.timeOrigin` reads from my own steps. In each batch the read comes just before its screenshot, so a screenshot lies between its own read and the next read. The game itself runs in a cross-origin iframe, so I could not read its state; "first playable frame" is the first screenshot that shows an interactive screen, and it is a bracket (the screenshot before it showed a loader, this one shows the screen), not a point. Tool latency inside a batch was 0.2 s on some steps and several seconds on others, so brackets are 2 to 12 s wide and "first input" times include my own step delay.
- Input: the computer tool in this session has click, double-click, key, scroll, hover and `left_click_drag`, and NO mouse-down, mouse-move or mouse-up action, so a multi-point stroke could not be made on any cross-origin game. `left_click_drag` is a two-point drag. It did not draw in any of the 3 draw games (details below). BYC is same-origin, so there I dispatched real `PointerEvent`s with 19 points at 20 ms spacing from JavaScript.
- A game tab with an unsaved-state handler cannot be closed or navigated: `tabs_close_mcp` timed out three times on Thief Puzzle and `navigate` reported a "Leave site?" dialog. `navigate` with `force: true` to a local page discarded it, then the tab closed. Later game tabs got a `beforeunload` neutraliser at injection and closed normally.

## 6. BYC against the peers

Each line is tagged. "Peers" are the 8 games above, all from this one Premium session.

BYC shows none: the first frame is level 1 [MEASURED].
