# Playgama's own QA tool run on the build, 9 Nov 2026

What: Playgama's QA harness (link from the MCP tool `get_local_game_qa_tool_link`, never built by hand) loading `dist/playgama/index.html` from `node tools/serve.js`, driven by `qa_play.mjs` in a Playwright Chromium. Level 1 was played with a drawn stroke, the result card was tapped, the harness then served an interstitial.

[MEASURED 9 Nov] Requirements List, "SDK Mandatory": all 4 ticked by the harness itself: SDK initializes properly; `Game Ready` message sent; Interstitial ad loads; Player progress saved via `bridge.storage`. "SDK Optional": language via `bridge.platform.language` ticked; rewarded ad loads NOT ticked (needs a skip offer after repeated failures, not played). The other optional features (social, leaderboards, payments, daily rewards, tasks, achievements, cross-promo, banner) are unticked because BYC does not use them (not required).
[MEASURED] Harness log, in order: Bridge v2.4.1 initialized; language en; `level_started a1-wall`; `game_ready`; storage read; load time 240-265 ms; initial download 34 B (it counts only extra files, not `index.html`); `level_completed a1-wall`; storage set; `interstitial loading` / `opened`; the harness then logs `Game: paused`, `Audio: disabled` for the ad; `level_started a5-hang` was sent while the ad was loading.
[NOT DONE] The "User Experience" block (13 items, e.g. field scale, overlap, pop-up close buttons, sound stops when minimised, mute button, playable on mobile) is ticked by a human in that tool and was not ticked; the "Scaling test" presets (Fit to screen, Playgama, 16:9, 1:1, iPhone 16 portrait and landscape) were listed but not exercised; "Platform Settings" (audio and pause toggles) was not exercised in the harness (covered separately by `tools/test/playgama.js`).
[MEASURED, cause UNVERIFIED] In the owner's own Chrome ("BDE-1208") the harness frame stayed blank and the local server never saw an iframe request, although opening `http://localhost:8080/...` directly in the same browser worked; most likely Chrome's local-network permission for an https page framing localhost, which needs a click in that browser. In a Playwright Chromium with the two feature flags it loads and plays.
